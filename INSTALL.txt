SECUREDLANDING MARKETPLACE LOAN LOOKUP FIX
Date: 2026-08-01

Problem fixed:
"Investment saved, but marketplace loan was not found."

ROOT CAUSE
marketplace_loans.id is a UUID and loan_application_id is the canonical internal
application ID, while some payment routes are passing the visible six-digit
loan_number (for example 352552 or 480946).

INSTALL
1. Run sql/marketplace_loan_lookup_fix.sql in the Supabase SQL Editor.
2. Copy src/lib/marketplaceLoanResolver.ts into your project at:
   src/lib/marketplaceLoanResolver.ts
3. In the payment code that currently searches marketplace_loans directly,
   import:
     resolveMarketplaceLoan
     updateMarketplaceFunding
   from ../lib/marketplaceLoanResolver (adjust relative path as needed).
4. Resolve the marketplace row BEFORE inserting/saving a new investment.
5. After successful payment/investment creation, call updateMarketplaceFunding
   with the same loan reference and amount.
6. For new navigation from InvestorMarketplace, prefer passing
   loan.loan_application_id. The resolver remains compatible with six-digit
   loan_number values.
7. Deploy.

IMPORTANT
The screenshots show that investments have already been saved while the
marketplace update failed. Do NOT repeat those failed-looking payments merely
to test. First reconcile existing investment records and marketplace funding
totals so the same investment is not counted twice.

This patch intentionally does not guess your current investment table schema,
so it does not overwrite NMIPayment.tsx/BitcoinPayment.tsx with an incompatible
full page. It fixes the shared identifier resolution safely and repairs missing
marketplace rows in SQL.
